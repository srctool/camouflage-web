# W1 findings

What the foundations milestone (srctool/camouflage-web#15) settled, and what it found on the way. The base notes in
`srctool/camouflage` carry the decisions; this is the record.

## Settled

| Question               | Decision                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The theme model        | 42 color roles, 15 text styles, five motion roles, shapes, spacing, elevation, **component themes** and **token sets**, as typed TypeScript. Every value is a CSS string; a theme becomes `--camo-*` variables (`themeDeclarations`, `applyTheme`, the provider's stylesheet). Renderers read `var()` references, never values.                                                                                                  |
| Type sizes             | **`rem`**, not `px`. A `px` size ignores the user's font-size setting (WCAG 1.4.4), so the text-scale axis of the screenshot suite would test nothing. At the default 16px root a style is the same number of pixels as in the notes.                                                                                                                                                                                            |
| Token sets             | `tokenSets: { brand: { "600": "#7c3aed" } }` becomes `--brand-600`, in the brand's own naming and unprefixed (ADR-32). A role refers to one with `var(--brand-600)`. A token set is any name with any steps; `validateTheme` reports two sets that write the same variable.                                                                                                                                                      |
| `fromSeed`             | Material tonal palettes (`@material/material-color-utilities`) with Camouflage's tone table. Its output equals the Dart library's for every seed in `tests/fixtures/seed-golden.json` (five seeds, light and dark, and tinted neutrals), which Dart generated. It is on its own entry, `@srctool/camouflage-core/seed`, because the utilities ship ESM Node cannot load and an app with ready-made themes should not carry them. |
| Starter themes         | Generated (`pnpm themes`), from `fromSeed` for Minimal and from Apple's tables for Cupertino, and checked in CI. The generated Minimal and Cupertino values equal the ones copied from Dart in W0, role by role.                                                                                                                                                                                                                 |
| `validateTheme`        | The same checks, in the same order, as `validate()`. Its issues equal Dart's for the shared cases in `tests/fixtures/validation-cases.json`. A color that is a `var()` of the theme's own token set is resolved; one the page defines is skipped. Cupertino fails Apple's known pairs only, the same list as the Dart skin's test.                                                                                               |
| The environment        | Each value is read through a small replaceable source (`setEnvironmentSources`): window size, input kind (`pointer: coarse` or `hover: none` is touch), platform, capabilities, and **reduced motion, kept live**. The server has no sources that answer, so it uses attributes and defaults.                                                                                                                                    |
| `camouflage(host)`     | A reactive controller with `skin`, `theme` (as values, for the scheme in force), `tokens(name)`, `environment`, `contentColor`.                                                                                                                                                                                                                                                                                                  |
| ADR-44 (`adjustTheme`) | **Not built**: the ADR is still proposed. `createCamoTheme` is its web equivalent.                                                                                                                                                                                                                                                                                                                                               |
| The skin contract      | `SkinComponents` lists a renderer per component and a milestone adds its line; `CamoSkin` needs all of them. `defineSkin` fails to compile and throws, naming the missing one; `InProgressSkin` compiles half built but cannot register; `pnpm skins` is the publish check. (Kotlin and Dart list all 54 at once; the web grows with its components.)                                                                            |
| Shared pieces          | Flat, Classic, Fade and Opacity are in core, so every skin that wants one imports it. Feedback now also reacts to `data-camo-pressed`, set by `PressController`, so a key press feels like a click.                                                                                                                                                                                                                              |
| The behavior layer     | `PressController`, focus helpers (`tabbables`, `initialFocusTarget`, `rememberFocus`), `RovingTabindexController` (mirrors in right-to-left), `ElementInternals` helpers (`setCustomState`, `reportFormState`), `contentVariables`.                                                                                                                                                                                              |
| Screenshots            | One scenario list; the Playwright runner over a Storybook harness story; Linux baselines from CI. See `docs/testing.md`.                                                                                                                                                                                                                                                                                                         |
| Contract               | `camouflage-contract.json` (draft schema), the manifest check against it, and generated typings for the DOM, React and Vue. See `docs/contract.md`.                                                                                                                                                                                                                                                                              |

## Found

- **A link button had a 24 px touch area on the inline axis.** Its text is short and it has no padding. The new touch-target
  check found it; the touch area now grows on both axes (`inset-inline: min(..., (100% - 48px) / 2)`).
- **The theme types did not list two fields the skins already read** (`minWidth` for a button, `elevation` for a dialog).
  The contract check found the drift.
- **`tabbables` kept an element inside a `hidden` ancestor.** Fixed, with a test.
- **axe cannot see a component's disabled state**, because it lives on `ElementInternals`. The conformance helper leaves a `[disabled]` host out of the contrast rule (a disabled control is exempt by WCAG 1.4.3).
- **Some base-note theme fields cannot be CSS variables**: `actionsLayout`, `titleAlign`, `defaultAppearance`,
  `showCloseButton`, `stackedScrim`. They change structure, and a renderer is a pure function that reads no styles. They are
  listed as gaps in the contract. The way to support them is for the provider to resolve them in JavaScript (the same place
  ADR-44's `adjustTheme` would run); that is a W4 decision, when the dialog is finished.

## Not done

- **The scenario list is not read by Kotlin or Dart yet.** The format is language-neutral and the names follow Kotlin's
  files; moving the list to the umbrella repository and having Roborazzi and Alchemist read it needs both suites to agree.
- **The Linux screenshot baselines.** They come from CI's first run (the `screenshots` artifact) and are committed after review.
- **Firefox** for the harness and the behavior tests runs in CI only (it cannot start in the local sandbox).
- **Tauri on Windows and Linux** and the WebKitGTK and WebView2 rows of the baseline (carried over from W0, srctool/camouflage-web#3).
- **The proposal to srctool/camouflage#64** for the contract schema. The draft is `contract/schema.json`; it has not been posted there.
