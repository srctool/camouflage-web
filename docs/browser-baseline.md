# Browser baseline

Decided at W0 (srctool/camouflage-web#3). The table is generated by `apps/tauri-sample/baseline.mjs` from the `web-features` package (the Baseline data behind MDN) and the live probe in `apps/tauri-sample/web/probe.js`, which uses each feature instead of reading a version number. "Baseline" is Baseline status; the three version columns are the first release with support.

Live columns come from Playwright's Chromium 159 and WebKit 27.2 and from the Tauri 2 window on macOS 27.2 (WKWebView). Firefox cannot launch in the development sandbox; it runs the whole test suite in CI. Regenerate with `pnpm --filter @srctool/camouflage-tauri-sample probe:browsers`, `cargo run` in `src-tauri` (with the sample server running; see the app's README section below) and `node baseline.mjs`.

## The scenario

The same scenario (the page hydrates, a button is focusable and has its skin, a dialog is a modal in the top layer with focus on the dismiss action) gives the same result in Chromium, WebKit and the Tauri macOS window: `hydrated: true`, button surface `rgb(255, 59, 48)` for Cupertino's error tone, `dialogModal: true`, focus on the action.

## Decision

**The baseline is Baseline widely available at the release date, for everything core uses.** A feature that is only newly available, or not Baseline, is progressive: it must have a fallback, and the page must work without it.

| Feature                                                                                                                                                     | Use                               | Decision                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Declarative shadow DOM, `ElementInternals`, ARIA reflection, `<dialog>` and `:modal`, constructable stylesheets, `:has()`, `color-mix()`, container queries | Required by core                  | Widely available. Floor today: Chrome and Edge 111, Firefox 123, Safari 16.4 (the oldest is declarative shadow DOM in Firefox 123, and Safari 16.4 for the rest). |
| Popover API (menus, tooltips, popovers; W4 and later)                                                                                                       | Required from W4                  | Newly available: Chrome 116, Firefox 125, Safari 17. The floor rises to those when the first popover component ships, and this table is re-checked then.          |
| CSS anchor positioning                                                                                                                                      | Placement of popovers             | Not Baseline (no Firefox). Core positions with a small script (measure, flip, shift) and uses anchor positioning only as an enhancement later.                    |
| `backdrop-filter`                                                                                                                                           | Blur materials (ADR-42)           | Newly available. The capability chain applies: `capabilities.backdropBlur` false gives the opaque surface.                                                        |
| SVG filters inside `backdrop-filter` (Liquid Glass refraction)                                                                                              | Cupertino Liquid Glass            | Chromium only in practice. `capabilities.runtimeShaders` is false elsewhere and the skin draws blur or opaque.                                                    |
| `prefers-reduced-transparency`                                                                                                                              | `capabilities.reduceTransparency` | Not Baseline (Chromium, and WebKit 27 per the probe). Progressive: absent means false.                                                                            |
| `scrollbar-width`, `scrollbar-color`                                                                                                                        | Scrollbar skin (W9)               | Newly available. The scrollbar renderer draws its own scrollbar and uses these only as the native fallback.                                                       |
| `closedby` on `<dialog>`                                                                                                                                    | not used                          | The dialog handles Escape and the scrim itself, so there is no gap: the probe says the Tauri macOS webview lacks it.                                              |
| View transitions, `light-dark()`, CSS nesting                                                                                                               | not used                          | Not required. The scheme is the provider's `data-camo-scheme`, and renderers emit flat CSS.                                                                       |

**Webviews (Tauri).**

- **WKWebView (macOS):** its engine is the OS's Safari, so the floor is a macOS version: Safari 16.4 is macOS 13.3, Safari 17 (popover) is macOS 14. Tauri's default macOS minimum is older, so the sample sets none and the release sets the macOS version from this table. Verified on macOS 27.2.
- **WebView2 (Windows):** evergreen Chromium, updated by the runtime, so it is never behind the Chrome and Edge column. Not run here (no Windows machine); the Chromium results apply.
- **WebKitGTK (Linux):** the engine follows the distribution's package, and it is the oldest. Tauri 2 needs `webkit2gtk-4.1`; the series that matches Safari 17 is 2.42 or newer (approximate mapping, not verified). **Not run:** no Linux machine was available, so this row is the open item. Before 0.2.0 run the probe on Ubuntu LTS and the oldest supported distribution, and raise the documented floor if a required feature is missing.

## Running the probe in Tauri

```bash
pnpm --filter @srctool/camouflage-ssr-sample start        # the spike page on :4173
cd apps/tauri-sample/src-tauri
CAMO_URL="http://localhost:4173/dialog?skin=cupertino&scheme=light" CAMO_OUT=../results-webview.json cargo run
```

The host opens a window on `CAMO_URL`, runs the probe and the scenario after load, writes the JSON and exits. A remote page may call only the `report` command (`capabilities/default.json`). Without `CAMO_URL` it loads `web/index.html`.
